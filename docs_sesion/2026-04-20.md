## Problemas resueltos

### 1. ConnectTimeout de Mattermost (raíz)

`MATTERMOST_WEBHOOK_URL` apuntaba al port-forward de Cloud Shell de la sesión anterior (`https://8065-cs-...cloudshell.dev`), que ya no existía. El ping al service base funcionaba porque era una URL diferente. La URL del hook tenía el scheme y host equivocados.

**Fix**: `kubectl set env` con la URL interna correcta (`http://mattermost-svc.arturo-mattermost.svc.cluster.local:8065/hooks/<TOKEN>`).

### 2. URL efímera → persistida en Secret

Creado `Secret/mattermost-webhook` en `arturo-llm-test`. `deployment-agent.yaml` actualizado con `secretKeyRef`. El token no está commiteado en git.

### 3. CreateContainerConfigError (runAsNonRoot + appuser)

Al aplicar el YAML con `secretKeyRef`, el nuevo ReplicaSet falló porque `runAsNonRoot: true` + usuario nombrado `appuser` (no numérico) impide que GKE verifique non-root.

**Fix**: `kubectl patch` añadiendo `runAsUser: 1000` (UID real de `appuser` confirmado vía `kubectl exec -- id`). También persistido en `k8s/deployment-agent.yaml` en el Mac.

### 4. Sincronización de repos (Mac → empresa)

Sin remote compartido. Flujo: `git archive --format=zip HEAD` en Mac → correo → descomprimir en repo empresa → `git push` → `git pull` en Cloud Shell. El `.venv/` se añadía a git por falta de entrada en `.gitignore` (corregido en el Mac, pendiente de llegar a empresa).
