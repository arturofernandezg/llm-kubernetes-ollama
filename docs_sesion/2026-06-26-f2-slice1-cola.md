> Sesión arrancada con `/start`; micro-objetivo elegido por Jay: **Slice 1 completo** de F2 (camino de cola Redis Streams E2E), tras flag, sin cluster. Diseño previo en bitácora `f2-diseno-cola` + plan `~/.claude/plans/cuddly-whistling-feather.md`.

## Objetivo
Implementar el camino de cola Redis Streams entre `/webhook/alert` y el pipeline, **detrás de `QUEUE_ENABLED=False` (default)**: enqueue + dedup cluster-wide + ensure_group + consume_loop in-process + handler que delega en el pipeline existente. Todo testeable con `AsyncMock`, sin tocar los 394 tests existentes.

## Hecho
- **`agent/config.py`** — 6 settings nuevos: `queue_enabled=False`, `queue_stream_key="aiops:alerts"`, `queue_group="aiops-workers"`, `dedup_window_seconds=300`, `queue_maxlen=1000`, `queue_max_deliveries=3` (este último ya definido por cohesión, se usa en Slice 2).
- **`agent/streams.py`** (nuevo, patrón `escalation_store.py` — funciones que reciben `redis_client`):
  - `consumer_name()` (lee `HOSTNAME`, default `agent-local`), `ensure_group()` (XGROUP CREATE MKSTREAM, ignora BUSYGROUP idempotente).
  - `enqueue_alert()` — **fail-closed**: dedup `SET aiops:seen:<fp> NX EX <window>` + `XADD MAXLEN ~ <maxlen>`; devuelve id, `None` si deduplicado, **propaga** si Redis cae.
  - `consume_loop()` — `XREADGROUP COUNT 1 BLOCK 5000 STREAMS key >`, procesa 1 a 1, `XACK` en éxito; handler que lanza → no ACK (queda pendiente para reclaim Slice 2) y sigue; `CancelledError` se propaga (parada limpia).
  - Métricas module-level: `aiops_queue_enqueued_total`, `aiops_queue_processed_total{outcome}`.
- **`agent/main.py`**:
  - `_handle_stream_entry(entry_id, fields)` — decodifica con `AlertItem.model_validate_json(fields["payload"])` y delega en `_process_alert_with_diagnosis` **sin tocarlo**; cuenta `QUEUE_PROCESSED{success|error}`.
  - Webhook (`handle_alert_webhook`) bifurca firing por flag: si `queue_enabled and app.state.redis` → `enqueue_alert` (503 fail-closed si XADD falla; `None`→dedup + `DEDUP_COUNTER`); else rama legacy (BackgroundTasks + `IN_FLIGHT_ALERTS`) intacta. Resolved sigue como notificación directa.
  - `lifespan`: tras conectar Redis, si flag+Redis → `ensure_group` + `asyncio.create_task(consume_loop(...))` en `app.state.consumer_task`; cancelado en shutdown como `cleanup_task`. Pre-init de labels de `QUEUE_PROCESSED`.
- **Tests**: `agent/tests/test_streams.py` (nuevo, ~11 con `AsyncMock`) + `TestWebhookQueuePath` (5) y `TestHandleStreamEntry` (2) en `test_endpoints.py`. Total +18.
- Verificado: `python3 -m py_compile` OK sobre los 5 ficheros tocados. Tests los corre Jay.

## Encontrado / gotchas
- **`FakeRedis` (tests/helpers.py) NO soporta operaciones de stream** (solo setex/get/delete/scan_iter) → los tests de cola usan `AsyncMock`, como ya anticipaba el diseño.
- **`json` no está importado en `main.py`** → para decodificar la entrada usé `AlertItem.model_validate_json()` (Pydantic v2) en vez de `json.loads`, evitando un import nuevo.
- **`asyncio.CancelledError` es `BaseException`, no `Exception`** → el `except Exception` de `consume_loop` no la captura, así que propaga y corta el bucle limpio. Los tests de `consume_loop` lo explotan: `side_effect=[resp, CancelledError()]` para terminar el loop de forma determinista.
- En el camino de cola, el `IN_FLIGHT_ALERTS.discard()` del `finally` de `_process_alert_with_diagnosis` es inocuo (discard de key inexistente no falla) → pipeline reutilizado sin cambios.

## Decisiones + por qué
- **`streams.py` no importa de `main`** (evita ciclo de imports): el **webhook** extrae el fingerprint (`alertname:ns:pod` vía `_extract_alert_meta`) y se lo pasa a `enqueue_alert`. Alternativa descartada: replicar `_extract_alert_meta` dentro de `streams.py` (duplicación).
- **Métricas de cola viven en `streams.py`** (no en `main.py` como `ESCALATION_STORE_COUNTER`): mantiene el módulo self-contained; `main` importa solo `QUEUE_PROCESSED` (lo que necesita el handler). `QUEUE_ENQUEUED` se incrementa dentro de `enqueue_alert`.
- **`enqueue_alert` fail-closed** (excepción consciente al fail-open del resto): no perder alertas prima → propaga, el webhook da 503 y Alertmanager reintenta.
- **Doble camino tras flag**: la rama legacy queda intacta para que los 394 tests pasen sin tocar; el camino de cola convive hasta validar en cluster (Slice 4).
