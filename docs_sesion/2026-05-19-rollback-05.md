# Sesión #5 — Rollback automático (2026-05-19)

## Objetivo

Cerrar el loop de auto-remediación: si el agente parchea un deployment y el pod sigue en estado fallido tras N minutos, revertir al valor previo capturado ANTES del patch y notificar a Mattermost.

## Decisiones tomadas y WHYs

### 1. asyncio.create_task + IN_FLIGHT_ROLLBACKS (vs sleep bloqueante en BackgroundTask)
**WHY**: El BackgroundTask de FastAPI que ejecuta `_process_alert_with_diagnosis` no bloquea la respuesta HTTP (ya corría en background), pero si la tarea espera 300s no puede procesar otras alertas que lleguen mientras tanto. `asyncio.create_task` libera el task inmediatamente y el polling ocurre de forma independiente. Mismo patrón que `PENDING_ESCALATIONS` — el código ya tenía la infraestructura.

### 2. Pod phase ≠ Running OR restartCount > 0 (vs re-check Prometheus alert)
**WHY**: kubectl-only, sin dependencia de red adicional al Prometheus endpoint. Un pod en `Failed`/`Pending` después de un patch de memoria es señal clara. Prometheus query añadiría NetworkPolicy update, httpx import, y parsing complejo de PromQL response — sobre-ingeniería para S5.

### 3. ExecuteResult dataclass frozen (vs seguir con string)
**WHY**: El master plan pedía "extender ExecuteResult", pero la estructura no existía — devolvía string sin estructura. El dataclass frozen permite igualdad por valor (simplifica tests), es inmutable (seguro para pasar entre async tasks), y deja base limpia para S6 (rollback puede inspeccionar `success`, `exit_code` sin parsing de regex).

### 4. Rule 4.5 NO aplica al rollback
**WHY**: `revert_patch` bypasa `decide_action` completamente — llama a `execute_commands` directamente. El rollback INTENCIONALMENTE reinicia el pod (vuelve a la config previa). Si aplicáramos rule 4.5, el rollback nunca podría ejecutarse. El patch original ya pasó rule 4.5 (de lo contrario habría sido ESCALATE, no AUTO_REMEDIATE).

### 5. Snapshot capturado en process_remediation, no en main.py
**WHY**: Mantener la lógica de captura cerca del executor es más seguro — si se añade otra ruta de ejecución en el futuro, captura el snapshot automáticamente. Separar en main.py requeriría duplicar la lógica de "¿habría AUTO_REMEDIATE?" para decidir si capturar antes.

### 6. selector = "app={deployment_name}" (convención, no query)
**WHY**: Queryar el selector del deployment requiere un subprocess adicional con jsonpath complejo para parsear `map[key:value]`. En el proyecto, todos los deployments siguen la convención `app=<name>`. Podemos hacer el query del selector en S6 si hay un caso real que lo requiera — no YAGNI aquí.
