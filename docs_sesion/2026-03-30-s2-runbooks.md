## Progreso

### ✅ Paso 1 — Formato YAML diseñado
Cada runbook es un fichero YAML con esta estructura:
```yaml
id: runbook-<error>-001          # → doc_id en ingest_runbook()
error_class: OOMKilled           # → metadata.error_class
service: kubernetes              # → metadata.service
severity: critical               # → metadata.severity
commands: [...]                  # → metadata.commands
text: |                          # → text (contenido que se embebe en ChromaDB)
  # Título
  ## What is happening / Common root causes / Investigation steps / Remediation
```
Decisión de diseño: el `text` incluye todo el conocimiento operativo en formato legible.
ChromaDB embeddeará este texto y lo buscará por similitud semántica cuando llegue una alerta.

### ✅ Paso 3 — Funciones de ingesta batch en `rag.py`
Dos funciones nuevas añadidas al módulo RAG:

- **`load_runbooks_from_dir(path)`** — función síncrona (pura I/O):
  - Lee todos los `*.yaml` de un directorio
  - Valida que cada fichero tenga los 6 campos requeridos (`id`, `error_class`, `service`, `severity`, `commands`, `text`)
  - Skipea con warning los ficheros con campos faltantes o formato inválido
  - Retorna lista de dicts

- **`ingest_all_runbooks(path, http_client, chroma_client)`** — función async:
  - Llama a `load_runbooks_from_dir()` para cargar los YAMLs
  - Para cada runbook, construye el dict de metadata y llama a `ingest_runbook()`
  - Nota: `commands` se convierte de lista a string separado por comas (ChromaDB metadata solo acepta strings/ints/floats)
  - Continúa si uno falla (resiliencia), loguea el error
  - Retorna stats: `{ingested, errors, total}`

Dependencia añadida: `PyYAML==6.0.2` en `requirements.txt`.
