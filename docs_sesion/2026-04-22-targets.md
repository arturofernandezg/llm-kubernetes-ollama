# Sesión 2026-04-22 — Fix Prometheus targets DOWN (KSM + agente)

## Objetivo
Dejar los dos targets de Prometheus UP antes de desplegar Grafana:
- `kube-state-metrics-svc:8080` — DOWN con `connection refused`
- `agent-svc:8000/metrics` — DOWN con `context deadline exceeded` (10s)

## Diagnóstico y causa raíz

### kube-state-metrics: ImagePullBackOff
`kubectl describe pod` reveló:
```
failed to do request: Head "https://registry.k8s.io/...": dial tcp 34.96.108.209:443: i/o timeout
```
Los nodos spot no tienen Cloud NAT → no pueden salir a internet. `registry.k8s.io` es inaccesible. Docker Hub (`prom/prometheus`) sí funciona porque GKE tiene acceso a Docker Hub vía mirror interno.

### agent /metrics: NetworkPolicy bloqueando a Prometheus
Los logs del agente mostraban `/readyz` y `/healthz` respondiendo en <20ms → event loop sano. El timeout no era bloqueo del loop sino que Prometheus no recibía respuesta porque la NetworkPolicy `agent-allow-ingress` solo permitía ingress desde `app: alertmanager` y Apache, **no desde `app: prometheus`**. La conexión se descartaba silenciosamente → timeout en vez de connection refused.

## Fixes aplicados

### 1. KSM → mirror a Artifact Registry (`k8s/prometheus.yaml`)

Imagen actualizada en `prometheus.yaml:430`:
```
image: europe-southwest1-docker.pkg.dev/uniovi-ai-infra-agent/aiops-agent/kube-state-metrics:v2.13.0
imagePullPolicy: Always
```

**Procedimiento de mirror** (ejecutar desde Mac con `gcloud auth configure-docker` hecho):
```
brew install crane
DST=europe-southwest1-docker.pkg.dev/uniovi-ai-infra-agent/aiops-agent/kube-state-metrics:v2.13.0
crane copy --platform linux/amd64 registry.k8s.io/kube-state-metrics/kube-state-metrics:v2.13.0 $DST
```

`crane` opera registry-to-registry sin pasar por caché local → evita el problema de arquitectura ARM64 vs AMD64 en Mac M4.

**Nota**: `docker pull --platform linux/amd64` + `docker tag` + `docker push` NO funcionó en Mac ARM (M4) — Docker Desktop no actualiza el tag local correctamente aunque se especifique la plataforma. Usar `crane` para futuros mirrors cross-platform.

### 2. scrape_timeout (`k8s/prometheus.yaml`)

Añadido al bloque `global:` en el ConfigMap `prometheus-config`:
```yaml
scrape_timeout: 20s
```
(antes no había — default 10s, demasiado corto si el agente está procesando un diagnóstico LLM)

### 3. NetworkPolicy scrape (`k8s/networkpolicy.yaml`)

Añadida regla `from` en `agent-allow-ingress`:
```yaml
# Prometheus scrape (namespace: arturo-monitoring)
- from:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: arturo-monitoring
      podSelector:
        matchLabels:
          app: prometheus
  ports:
    - protocol: TCP
      port: 8000
```

## Comandos de despliegue

```
kubectl apply -f k8s/prometheus.yaml
kubectl rollout restart deploy/prometheus -n arturo-monitoring
kubectl rollout restart deploy/kube-state-metrics -n arturo-monitoring
kubectl rollout status deploy/kube-state-metrics -n arturo-monitoring
kubectl apply -f k8s/networkpolicy.yaml
kubectl get pods -n arturo-monitoring
```
