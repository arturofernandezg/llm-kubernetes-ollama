## Lo que se hizo

### Bloque 1 — `build_incident_document()` en `rag.py`
- Funcion que toma `(alert, diagnosis, remediation)` y devuelve `(doc_id, text, metadata)`
- `doc_id`: `incident-{alertname}-{epoch}` — determinista, upsert-safe
- `text`: resumen human-readable (alert + severity + description + diagnosis + risk/confidence + commands + action + execution_log)
- `metadata` (primitivos ChromaDB): `error_class`, `outcome`, `fix_applied`, `confidence`, `risk`, `timestamp`
- Outcome mapping: `AUTO_REMEDIATE → "auto_remediate"`, `ESCALATE → "escalate"`, `SUGGEST_ONLY → "suggest_only"`, `None → "no_remediation"`

### Bloque 2 — Integracion en `main.py`
- Imports: `build_incident_document`, `ingest_incident` desde `rag`
- `FEEDBACK_COUNTER` Prometheus con labels: `persisted`, `skipped`, `failed`
- Bloque feedback en `_process_alert_with_diagnosis()` tras remediacion, antes de Mattermost:
  - Si `diagnosis is not None`: construye doc + llama `ingest_incident()` + inc `persisted`
  - Si falla: log warning + inc `failed` — fail-open, Mattermost sigue recibiendo
  - Si `diagnosis is None`: inc `skipped`
- `ingest_incident` llamado con kwargs para testabilidad
