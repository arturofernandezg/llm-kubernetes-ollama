### Bloque 2 — Mattermost: webhook entrante (~10 min)

#### 2.1 Acceder a Mattermost UI

Desde Cloud Shell:
```bash
kubectl port-forward -n arturo-mattermost svc/mattermost-svc 8065:8065
```

Luego usar "Web Preview" de Cloud Shell (icono en la barra superior → Preview on port 8065).

**Nota**: Jay abrió Mattermost una vez antes. Si no recuerda credenciales, revisar
si hay un admin por defecto o hay que crear uno (la primera vez Mattermost pide
crear un admin account).

#### 2.2 Crear Incoming Webhook

En Mattermost UI:
1. Ir a **Main Menu → Integrations → Incoming Webhooks → Add Incoming Webhook**
2. Seleccionar el canal (ej. `Town Square` o crear uno `#aiops-alerts`)
3. Copiar la URL generada (formato: `http://localhost:8065/hooks/<token>`)

**Importante**: la URL que usamos en el agente es interna del cluster, NO localhost:
```
http://mattermost-svc.arturo-mattermost.svc.cluster.local:8065/hooks/<TOKEN>
```

#### 2.3 Setear la env var en el deployment

Opción rápida (sin tocar el YAML del repo):
```bash
kubectl set env deployment/agent -n arturo-llm-test MATTERMOST_WEBHOOK_URL="http://mattermost-svc.arturo-mattermost.svc.cluster.local:8065/hooks/<TOKEN>"
```

Esto hace un rolling update automático.

Verificar que el pod arranca con la env seteada:
```bash
kubectl describe deployment agent -n arturo-llm-test | grep MATTERMOST
```

### Bloque 3 — Cargar runbooks en ChromaDB (~10 min)

#### 3.1 Ingesta de los 16 runbooks

**Si el Dockerfile actualizado ya tiene los runbooks en `/app/runbooks/`:**

```bash
kubectl exec -n arturo-llm-test deploy/agent -- python -c "import asyncio,httpx;from rag import ingest_all_runbooks,get_chroma_client;r=asyncio.run(ingest_all_runbooks('/app/runbooks/',httpx.AsyncClient(timeout=60.0),get_chroma_client()));print(r)"
```

Esperado: `{'ingested': 16, 'errors': 0, 'total': 16}`

**Si el Dockerfile NO se actualizó a tiempo** (alternativa con kubectl cp):
```bash
# Obtener nombre exacto del pod
POD=$(kubectl get pod -n arturo-llm-test -l app=agent -o name | head -1)

# Copiar runbooks al pod (solo /tmp es writable por readOnlyRootFilesystem)
kubectl cp agent/runbooks/ arturo-llm-test/${POD#pod/}:/tmp/runbooks/

# Ejecutar ingesta desde /tmp
kubectl exec -n arturo-llm-test deploy/agent -- python -c "import asyncio,httpx;from rag import ingest_all_runbooks,get_chroma_client;r=asyncio.run(ingest_all_runbooks('/tmp/runbooks/',httpx.AsyncClient(timeout=60.0),get_chroma_client()));print(r)"
```

#### 3.2 Verificar

```bash
kubectl exec -n arturo-llm-test deploy/agent -- python -c "import chromadb;c=chromadb.HttpClient(host=\"chromadb-svc\",port=8000);print('runbooks:',c.get_collection('runbooks').count(),'incidents:',c.get_collection('incidents').count())"
```

podría tardar ~1-2 min. Si hay timeout, verificar que Ollama está ready y el modelo cargado.

## Posibles problemas y fallbacks

| Problema | Diagnóstico | Fallback |
|---|---|---|
| RBAC denied (no permission) | `kubectl auth can-i create role -n arturo-llm-test` | Preguntar al tutor; remediation funciona sin RBAC en dry-run mode |
| Cloud Build falla | Revisar logs en Cloud Console | Corregir error, re-submit |
| Mattermost no abre / no recuerda credenciales | Verificar pod logs: `kubectl logs -n arturo-mattermost deploy/mattermost` | Borrar el PVC de Mattermost y recrear (último recurso) |
| Ollama timeout en embeddings | `kubectl logs -n arturo-llm-test deploy/ollama --tail=10` | Verificar que `nomic-embed-text` sigue cargado: `kubectl exec deploy/ollama -n arturo-llm-test -- ollama list` |
| ChromaDB vacío tras ingesta | Revisar logs del exec, posibles errores de embedding | Ingesta manual: uno por uno con curl al endpoint |
| LLM genera JSON inválido | Logs: `Diagnosis generation failed` | El pipeline es fail-open: enviará la alerta sin diagnóstico |
| curl no existe en imagen agent | Python 3.11-slim no siempre tiene curl | Usar `python -c "import httpx;..."` como alternativa |
