# Sesión 2026-04-22 — Setup Mac personal como estación única

## Objetivo
Migrar el entorno de trabajo del flujo 2-PC (Mac personal + PC empresa) a solo el Mac personal ARM, con acceso directo a GCP/GKE.

## Contexto
El tutor confirmó que Jay puede usar su Mac personal directamente para el proyecto. Antes: desarrollo en Mac, despliegue en PC empresa con Cloud Shell.

## Lo que se hizo

### 1. Instalación gcloud + kubectl
- `brew install --cask google-cloud-sdk`
- kubectl instalado vía `gcloud components install kubectl`
- PATH configurado: `export PATH="/opt/homebrew/share/google-cloud-sdk/bin:$PATH"` → `~/.zshrc`
- Nota: el cask de Homebrew instala en `/opt/homebrew/share/google-cloud-sdk/bin/`, NO en `/opt/homebrew/Caskroom/...`

### 2. Conexión al cluster
```
gcloud container clusters get-credentials ai-infra-agent --zone europe-southwest1-a --project uniovi-ai-infra-agent
```
Verificado: 3 pods running en `arturo-llm-test` (agent, chromadb, ollama).

### 3. Migración de remote git
- Repo personal `jay66ss/LLM_Agent_Obserb` → repo empresa `arturofernandezg/llm-kubernetes-ollama` (público)
- Problema: macOS Keychain tenía credenciales de `jay66ss` cacheadas
- Solución: token PAT de `arturofernandezg` embebido en la URL del remote:
  `git remote set-url origin https://arturofernandezg:TOKEN@github.com/arturofernandezg/llm-kubernetes-ollama.git`

### 4. Rebase y resolución de conflictos
- `git pull --rebase origin main` — conflictos en `.gitignore`, `CLAUDE.md`, `agent/diagnosis.py`, `docs/07-roadmap.md`, `k8s/deployment-agent.yaml`
- `.gitignore`: fusión manual (union de ambas versiones)
- Resto: `git checkout --ours` (se priorizó la versión del Mac personal)
- Vim durante rebase: solución `GIT_EDITOR="true" git rebase --continue`
- Push exitoso a `arturofernandezg/llm-kubernetes-ollama`

## Estado final
- Mac personal tiene acceso completo a GKE
- Remote apunta al repo de empresa (público)
- Código local sincronizado con el repo de empresa
