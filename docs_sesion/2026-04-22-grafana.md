# Sesión 2026-04-22 — Grafana (Fase 1 observabilidad)

## Objetivo

Desplegar Grafana en `arturo-monitoring` con datasource Prometheus, dashboard provisionado con métricas `aiops_*` y contact point webhook hacia el agente.

## Decisiones tomadas

| Aspecto | Elección | Motivo |
|---|---|---|
| Persistencia | `emptyDir` | Patrón enterprise: Grafana stateless + provisioning-as-code. PVC local = drift sin escalabilidad real. El equivalente enterprise añadiría PostgreSQL externo como backend. |
| Auth admin | Secret manual `grafana-admin` | Mismo patrón que `secrets-setup.sh`: nada sensible en repo. |
| Alerting rules | Solo contact point, sin reglas Grafana | Prometheus/Alertmanager es la fuente única de reglas. Evita doble notificación y fuente de verdad duplicada. |
| Imagen | `grafana/grafana:11.2.0` | Docker Hub accesible desde nodos (misma razón que `prom/prometheus`). No requiere mirror a AR. |

## Recursos creados

### `k8s/grafana.yaml` (nuevo)

Manifiesto único con todos los recursos en `arturo-monitoring`:

1. **ConfigMap `grafana-datasources`** → `/etc/grafana/provisioning/datasources/datasources.yaml`
   - Datasource Prometheus apuntando a `prometheus-svc.arturo-monitoring.svc.cluster.local:9090`
   - `isDefault: true`, `access: proxy`, `timeInterval: 30s`

2. **ConfigMap `grafana-dashboards-provider`** → `/etc/grafana/provisioning/dashboards/provider.yaml`
   - Provider que lee `/var/lib/grafana/dashboards/*.json`

3. **ConfigMap `grafana-dashboard-aiops`** → `/var/lib/grafana/dashboards/aiops.json`
   - Dashboard `uid: aiops-agent-overview`, "AIOps Agent — Overview"
   - 4 filas / 9 paneles:
     - **Pipeline AIOps**: `rate(aiops_diagnosis_total[5m])`, `rate(aiops_remediation_total[5m])`, `rate(aiops_feedback_total[5m])`
     - **Latencia Webhook**: `histogram_quantile(0.95/0.50, ...)` de `http_request_duration_seconds_bucket{handler="/webhook/alert"}` + `rate(http_requests_total{handler="/webhook/alert"}[5m])`
     - **Salud del Sistema**: stat `up{}` por job + table `kube_pod_status_phase{namespace=~"arturo-.*"}`
     - **Debug Interno**: `rate(aiops_ollama_retries_total[5m])` + `rate(aiops_extraction_total[5m])`

4. **ConfigMap `grafana-contact-points`** → `/etc/grafana/provisioning/alerting/contact-points.yaml`
   - Contact point `aiops-agent-webhook` tipo `webhook` → `agent-svc.arturo-llm-test.svc.cluster.local:8000/webhook/alert`
   - Sin reglas de alerting en Grafana — las 5 reglas AIOps siguen en Prometheus.

5. **Deployment `grafana`**
   - `runAsUser: 472`, `fsGroup: 472` (UID oficial Grafana)
   - `emptyDir` en `/var/lib/grafana` + ConfigMap en `/var/lib/grafana/dashboards` (nested mount — válido en K8s)
   - Env sensible desde Secret `grafana-admin` (secretKeyRef)
   - Tolerations `cloud.google.com/gke-spot`

6. **Service `grafana-svc`** — ClusterIP puerto 3000

### `k8s/networkpolicy.yaml` (modificado)

Añadida regla en `agent-allow-ingress` (`arturo-llm-test`):
- `app: grafana` en `arturo-monitoring` → `port: 8000`
- Necesaria para que el "Test" del contact point en la UI de Grafana llegue al webhook del agente.

## Secret prerrequisito

Ejecutar en Cloud Shell antes del primer `kubectl apply`:

```
kubectl create secret generic grafana-admin -n arturo-monitoring --from-literal=admin-user=admin --from-literal=admin-password='<pass-fuerte>'
```

## Comandos de despliegue

```
kubectl create secret generic grafana-admin -n arturo-monitoring --from-literal=admin-user=admin --from-literal=admin-password='<pass>'
kubectl apply -f k8s/grafana.yaml
kubectl apply -f k8s/networkpolicy.yaml
kubectl rollout status deploy/grafana -n arturo-monitoring --timeout=120s
kubectl get pods -n arturo-monitoring
kubectl port-forward svc/grafana-svc 3000:3000 -n arturo-monitoring
```

## Checks de verificación

1. `http://localhost:3000` — login con credenciales del secret.
2. **Connections → Prometheus → Test** — debe devolver verde.
3. **Dashboards → "AIOps Agent — Overview"** — visible sin importar nada.
4. Paneles `up{}` y `kube_pod_status_phase` pintando datos inmediatamente.
5. Paneles `aiops_*` con datos después de disparar una alerta de prueba:
   ```
   kubectl port-forward svc/alertmanager-svc 9093:9093 -n arturo-monitoring
   curl -X POST http://localhost:9093/api/v2/alerts -H "Content-Type: application/json" -d '[{"labels":{"alertname":"KubePodOOMKilled","pod":"test-pod","namespace":"arturo-llm-test","severity":"critical"},"annotations":{"summary":"Test OOM","description":"Test."},"startsAt":"2026-04-22T10:00:00Z"}]'
   ```
6. **Alerting → Contact points → aiops-agent-webhook → Test** — debe llegar al agente. Verificar: `kubectl logs -n arturo-llm-test deploy/agent --tail=50 | grep webhook`
